# 互动小说世界状态重构方案 — 三状态实时更新 + 确定性优先

> 版本：v1.1（2026-08-04，**P0 已实施完成**，50 项测试通过）
> 关联：backend/ + android/app/src/main/python/ 双目录同步改（已同步）
> 原则：**状态变化由确定性规则驱动，LLM 只负责填内容，不负责改状态**
> 实施记录：见 git commit db2b4a0（v3.6）

---

## 1. 问题确认（诊断结论）

**元凶**：行动识别异常 + LLM 对世界状态缺乏确定性把握，两者互为因果。

| 症状 | 根因 | 层面 |
|:-----|:-----|:-----|
| "我要回家了"只有角色回应，场景不变 | LLM 判定保守退回对话 / 判成行动但 location 靠 LLM 猜 | 识别层 |
| AI 对剧情走向把握不准、状态漂移 | 时间/地点/人物三状态无确定性更新规则，依赖 LLM 自觉 | **状态层（从未修过）** |
| 幻觉：LLM 写出玩家未做之事/角色未在场 | 场景生成 prompt 的状态注入不全、不及时 | 生成层 |

**历史教训**：v3.4 行动引擎以来所有补丁都在"识别层"（动词表/护栏/白名单），
状态层从未动过——所以"识别对了但状态没变"的现象反复出现。

## 2. 核心设计：状态三支柱（State Triad）

```json
state["world"] = {
  "time":    { "label": "傍晚", "slot": 4, "day": 3, "weather": "" },
  "location": "茶楼",
  "chars": {
    "林晚晚": { "present": true, "location": "茶楼", "mood": "平静", "relation": 62 },
    "掌柜":   { "present": false, "location": "柜台", "mood": "",    "relation": 40 }
  }
}
```

**三条铁律**：
1. **地点**：只有 travel 类行动 + 图谱校验通过才能改；LLM 输出一律不直接写入 location
2. **时间**：由规则推进（移动 +1 档、长事件 +1 档、对话不推进），LLM 不输出时间
3. **人物在场**：由"角色↔地点绑定 + 跟随规则"计算，不是 LLM 说了算

## 3. 状态更新时机（5 个确定性事件点）

| 事件点 | 更新内容 | 现有代码位置 |
|:-------|:---------|:-------------|
| ① 行动应用（apply_action） | 地点/时间/在场/物品 同步更新（**同步**，不等后台） | action_engine.apply_action |
| ② 场景推进（generate_scene） | 场景结尾抽取"发生了啥"→ 更新人物状态/mood/时间 | story_director.generate_scene_stream |
| ③ 对话结束（end-chat PACT） | 关系值/事实/承诺 → 写回 | interactive.py end-chat |
| ④ 开场初始化 | 图谱构建 + 三支柱初始化 | interactive.py start |
| ⑤ 回滚/重开 | 快照恢复即三支柱恢复 | interact_store.rollback |

**改造核心**：现有 ① 的部分更新在"后台线程"（_extract_player_state），
改成**行动应用时同步提取**（同步 = 场景生成前状态已新）。

## 4. 地点图谱（Location Graph）

```json
state["locations"] = {
  "茶楼": { "desc": "临街二层木楼，二楼雅间临窗", 
            "connected": ["街市", "城西码头"], 
            "chars": ["林晚晚", "掌柜"], "items": [] },
  "家":   { "desc": "城南小院，院里有棵桂花树",
            "connected": ["街市"], "chars": ["母亲"], "items": [] }
}
```

- **初始化**：start 时从 bible.geography + plan.outline 章节场景地点合并构建；
  起始地点 = state.location，起始地点相关地点（"回家"→ 家）若 bible 未给，用
  **LLM 一次性补全**（初始化时问一次，不是每轮问）
- **半开放注册**：玩家要去图谱外的地点（"去北山"）→ 图谱无此节点 →
  **回问确认**（"北山离这里很远，你确定要去？"）→ 确认后注册新节点（连到当前地点）
- **移动执行**：travel 目标 = 图谱节点名 → 校验 connected 或 known_locations →
  通过 → 更新 location + 时间推进 + 人物在场重算 → 到达场景生成

## 5. 时间推进（确定性规则）

```
时间档位表: 清晨(1) → 上午(2) → 正午(3) → 下午(4) → 傍晚(5) → 夜晚(6) → 深夜(7)
推进规则:
  - travel 行动: +1 档（长途移动可 +2，规则按图谱边距离）
  - 场景推进: 每 2 个场景 +1 档（长对话/战斗场景 +1）
  - 玩家输入"天黑了/过了一天"类: 不直接采信，LLM 输出作候选，规则校验单调性
  - 跨档：夜晚 → 次日清晨 → day+1
```

现有 time_valid 单调校验保留，新增**推进器**（time_advance 规则函数），
LLM 不再自由输出时间。

## 6. 人物在场（在场性 = 图谱绑定 + 跟随规则）

```
角色绑定地点: chars[角色] = {location: 图谱节点名}
在场判定: present = 角色.location == state.location（或 in 同一场景组）
跟随规则（玩家移动时）:
  - with 列表中的角色 → 跟随（location 同步更新）
  - 关系 > 70 且剧情无冲突 → 可能跟随（规则判定）
  - 其他角色 → 留在原地
移动后: compute_present 基于图谱重算（替代现有推导）
```

## 7. LLM 输出收窄（防幻觉的关键）

| 模块 | 现状 | 改后 |
|:-----|:-----|:-----|
| detect_action | 输出 location/flags/inventory/relations（LLM 自觉） | **只输出 intent + summary**；状态字段由规则引擎解析（travel→图谱、use→物品库校验） |
| 场景生成 | 状态注入不全 | 注入完整三支柱快照（当前地点 desc/在场角色/时间/天气/物品） |
| PACT 提取 | 全量信任 | 提取结果做规则校验（关系 clamp、事实去重、与状态矛盾时降级为"角色说法"） |
| 状态卡更新 | 后台异步 | 行动/场景提交时**同步**更新 |

**防幻觉三层**：
1. **写入层**：LLM 输出不直接写状态（护栏已有雏形，升级为"LLM 输出仅候选"）
2. **注入层**：生成前注入确定性状态快照（LLM 想写错也缺依据）
3. **校验层**：状态变化全部过规则（时间单调/地点图谱/在场性），矛盾即拒绝或降级

## 9. 验收标准（回归用例摘选）

| 输入 | 前置状态 | 断言 |
|:-----|:---------|:-----|
| 我要回家了 | location=茶楼, 图谱有"家" | location→家; 时间+1档; 林晚晚(若with)在场; 到达场景含环境描写 |
| 去城西码头 | 图谱: 茶楼-码头相连 | location→码头; 场景含码头 desc |
| 去北山 | 图谱无北山 | 触发回问确认, 不直接改地点 |
| 我饿了 | 任意 | 判对话(或行动但无状态变化), 角色回应 |
| 存档/读档 | 任意 | 走元指令, 不进剧情 |
