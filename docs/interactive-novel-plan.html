1. 一句话定位 & 核心体验

互动小说 = 现有写作管线 + 对话引擎 + 角色语音：用户用现有系统生成世界观与开头，剧情推进到关键节点时暂停，进入与角色自由对话环节；玩家的对话内容被实时写入剧情状态，决定后续走向。全程对话有角色专属语音（edge-tts 自动匹配音色，玩家可换）。

与传统 Galgame 的本质区别：传统 Galgame 是"预写选项树"——制作方写好所有分支，玩家在有限选项里选；互动小说是AI 实时生成分支——没有预写剧本，玩家的每一句话都是分支输入，剧情每次游玩都不一样。

传统 Galgame

选项树（预写）

选项A→结局1
选项B→结局2

分支数固定，写多少是多少；开发成本随分支指数级上升。

AI 互动小说（本次方案）

状态流（实时生成）

对话→状态更新→LLM 生成下一场景

剧情状态（关系值/flag/目标）随对话演化，生成器每次产出新内容——分支无限，永不重复。

核心体验闭环

生成世界观→ 自动写开场→ 关键节点→ 与角色对话（带语音）→ 剧情状态改写→ 生成下一场景→ …循环…
关键点：用户明确要求"朗读系统不朗读正文，只在对话时生效"——叙事段落纯文字展示（打字机效果），只有角色台词自动播语音，旁白静默。语音 = 对话专属，这也符合 Galgame 的经典体验（BGM 下的语音对白）。

2. 最终效果演示（用户视角完整流程）

下面是一次完整游玩的实际观感模拟（假设用户生成了一本《长安夜行录》武侠探案世界观）：

场景 3 · 旁白（无语音）长安城灯火渐熄，你受命潜入「锦绣坊」打探绣衣使失踪的线索。坊内烛影摇红，一名戴白纱斗笠的女子正独自斟茶。

关键节点触发🔊 语音自动开启

🎙苏晚（女 · 声线: 温柔御姐 · Xiaoxiao 音色，玩家可点 🎙 更换）： 「这位客官，深更半夜来我这锦绣坊，是买布，还是买消息？」

（台词边输入边自动播放语音，玩家可点 🔊 重播）

玩家对话你：「我不是来买消息的。三天前失踪的绣衣使，最后一晚来过这里——我要知道他见过谁。」

🎙苏晚：「呵……绣衣使？我这坊里夜夜客人不断，记性再好，也记不住每一张脸呀。」

玩家对话你：「（压低声音）我认得他左手的银环。你这里若是没有，我转身就走——但金吾卫的人明天就会来。」

🎙苏晚：（指尖一顿，茶水溅出半滴）「……坐。消息可以谈，就看你拿什么换。」

玩家对话你：「我身上只有一锭碎银。不过——我可以替你办一件事，任何事。」

🔊 语音：苏晚 · Xiaoxiao苏晚：「成交。后日亥时，城隍庙东墙下等我。」

对话结束 · 点击「继续剧情」

场景 4 · 旁白（无语音）你转身离开锦绣坊。身后的灯火一寸寸熄灭，而你知道——今夜之后，长安城里多了一个愿意替你做任何事的女人，也多了一笔还不起的债……

状态面板更新关系：苏晚 +18（泛泛之交 → 有所交易）；flag：已承诺替苏晚办一件事；目标更新：查绣衣使失踪案（线索：苏晚 → 城隍庙东墙）

体验要点：① 叙事是"小说"（旁白优美、无语音）；② 关键时刻自动切对话（语音自动匹配人设）；③ 玩家说什么真的会改变剧情（说"威胁"与说"示好"走向完全不同）；④ 关系值/flag 可见，养成感强；⑤ 每一局的剧情都是新的，可反复重开。

4. 总体架构设计

两条生成链路

场景生成链路→ State + 前情摘要 + 用户对话要点→ LLM 生成叙事段落 + 台词→ SSE 流式 → 前端打字机
对话链路→ 用户输入→ 角色卡 + 声音卡 + 剧情状态→ LLM 扮演回复（SSE）→ 台词落盘 → 异步预合成语音→ 播放 🎙

5. 核心机制：剧情引擎（对话驱动分支）

5.1 场景状态机

SCENE 生成→ NODE 关键节点检测→ CHAT 自由对话→ PACT 回扣→ SCENE 下一场景…
状态触发时机行为
SCENE开场 / 对话结束后LLM 生成 300-600 字叙事段落（旁白 + 角色台词），流式输出
NODE每段 SCENE 完成后LLM 判定（或规则兜底：每 2 段必出）是否为关键节点 → 是则进入 CHAT
CHAT关键节点进入对话模式，玩家与在场角色自由对话（无轮数上限）
PACT玩家点「继续剧情」PACT 提取：对话 → 剧情事实（承诺/行动/秘密，逐条带来源）+ 关系值/目标变更，写回剧情状态（§5.3）

5.2 关键节点检测（NODE 判定）— 三重保障，确保"该停时必停、不该停不乱停"

问题：LLM 自由判定不可靠——可能该进入对话时忘了停，也可能无事发生却频繁打断。方案：规则预筛 + LLM 精判 + 玩家主动权三层叠加，任何一层都能兜住另外两层的失误。

① 规则预筛（零成本）→ ② LLM 精判（只对候选）→ ③ 玩家主动介入（最终兜底）
层机制兜住什么
① 规则预筛硬规则无条件触发：开场第 1 段必触发；连续 2 段无对话必触发；场景中出现新角色/新冲突关键词（LLM 场景输出自带结构标签）必触发；玩家已进入对话则跳过LLM 判定失效（返回异常/超时/乱答）时，节奏下限依然保证——每 2 段必有互动
② LLM 精判只对未命中硬规则的场景调用轻量判定：{"is_node": bool, "chars": [...], "suggested_rounds": 1-8, "confidence": 0-1}；confidence<0.4 且距上次对话<2 段 → 不触发（防止频繁打断）规则误伤（为对话而对话的注水场景）——LLM 判断"这里真值得聊"才放行
③ 玩家主动权任何时刻（场景播放中/结束后）都有「💬 我要说话」按钮 → 立即进入对话模式；对话中随时可「▶ 继续剧情」提前退出系统误判的最后兜底——玩家想聊永远能聊，不想聊永远能走

成本：规则预筛命中率通常 40-60%，LLM 精判调用次数减半；三层任意一层通过即可进入对话。

5.3 对话如何真实作用到剧情 — PACT 因果闭环（核心创新点）

问题：早期方案只做"MERGE 提取状态"（关系值/flag），存在三个致命漏洞：① 提取不可靠——玩家说的承诺可能被 LLM 漏提；② 注入≠生效——状态写进 state.json 了，下一段生成时 LLM 可能无视；③ 玩家不可见——关系值变了，剧情里却没体现，玩家感觉"说了等于白说"。

方案：PACT 因果闭环——提取剧情事实 → 事实生命周期 → 双通道注入 → 回扣验证 → 玩家可见，五环节层层咬合：

① PACT 提取→ ② 事实生命周期→ ③ 双通道注入→ ④ 回扣验证→ ⑤ 玩家可见

① PACT 提取器（对话结束，1 次 LLM 调用）

不是简单提取关系值，而是从整段对话提取结构化剧情事实，每条带来源（对话轮次）与重要性：

// PACT 提取输出（示例，替代原 MERGE）
{
  "facts": [
    { "type": "promise",   "subject": "player", "target": "苏晚",
      "content": "答应替苏晚办一件事", "severity": "high", "source_chat": 12 },
    { "type": "action",    "subject": "player", "target": "苏晚",
      "content": "威胁要用金吾卫压她", "severity": "medium", "source_chat": 9 },
    { "type": "secret",    "subject": "苏晚", "target": "player",
      "content": "苏晚透露绣衣使是被人灭口的", "severity": "high", "source_chat": 15 }
  ],
  "relations": { "苏晚": "+18" },
  "objective_update": "城隍庙东墙（后日亥时）",
  "tone": "试探/交易"
}

PACT = Promise（承诺）/ Action（行动）/ Change（关系变化）/ Trust（秘密信任）。提取 prompt 硬约束：玩家明确说过的话必须逐条提取，不得遗漏；空泛客套（"改天请你喝茶"）标记 low severity，不强制回扣。

② 事实生命周期（本地逻辑，零成本）

状态含义流转
active已提取、待兑现/待体现默认初始态；携带 due_scene（应回扣场景号）
fulfilled剧情中已兑现/已呼应回扣验证通过 → 标记，附 evidence（第几段兑现）
expired承诺超期未兑现超过 due_scene 仍 active → 触发剧情后果（角色失望/关系下降），再标记
broken玩家违约（后续对话推翻承诺）新对话检测到矛盾 → 标记，角色态度转变的依据

③ 双通道注入（每段场景生成）

  • 显式通道（硬挂钩）：active facts 以"待兑现事项"结构化注入生成 prompt，并要求「本段必须自然回扣至少 1 个 active fact」——承诺被兑现/被提及/被利用，行动产生后果，秘密被利用或泄露
  • 隐式通道（软影响）：facts 进入角色行为决策——玩家威胁过苏晚 → 苏晚对玩家戒备 + 说话带刺；玩家守约 → 苏晚态度回暖。关系值只是"结果指标"，facts 才是"原因"

④ 回扣验证器（并入目标锚定检查，不增调用）

场景生成后，目标锚定检查同时校验："本段是否体现了至少一个 active fact？未体现 → 附修正指令重写 1 次；连续 2 段零回扣 → 强制插入一段'回扣场景'（调度器指定兑现哪个事实）。"事实 vs 关系值 vs 场景原文三方一致才算闭环。

⑤ 玩家可见（UI 反馈闭环）

  • 状态面板分两栏：「剧情状态」（目标/flags/关系） + 「你的影响」（facts 列表，带状态徽章：⏳ 待兑现 / ✅ 已兑现 / 💔 已破裂）
  • 剧情中角色提到玩家之前说的话时，前端高亮该句并标注「🔗 呼应你之前说过的」——玩家直观看到"我的话在生效"
  • 承诺兑现瞬间弹出提示：「✅ 你答应苏晚的事，兑现了」
为什么这样设计：① 分支无限——事实是连续积累的，LLM 每次生成都是新剧情；② 成本线性——只存 facts 不存分支树，上下文固定 3-4k tokens；③ 玩家自由度最大且说话算数——说什么都有效、且能被看见有效，而不是从 3 个选项里选完就忘。因果闭环四问：提取了没漏？注入了没无视？回扣了没验证？验证了没让玩家看见？

5.4 场景生成 Prompt 组装

system: 你是互动小说导演（风格注入：genre_playbooks + 小说 style）
user:
  剧情状态: {关系值/目标/地点}
  待兑现事实（active facts）: {PACT 输出，硬挂钩：本段必须回扣至少 1 个}
  前情摘要: {Summarizer 压缩的最近场景}
  出场角色卡: {苏晚的人设卡摘要}
  角色声音表: {CharacterVoices 声音卡}
  → 输出叙事段落 + 角色台词（标注说话人）

固定 ≈ 3-4k tokens/轮，成本可控。每 5 个场景触发一次摘要压缩。

5.5 剧情走向不偏移 — 目标锚定 + 状态校验 + 熔断回拉

问题：LLM 多轮生成会"忘目标"——写着写着主线丢了、flag 被无视、关系值前后矛盾。方案：三管齐下。

机制实现兜住什么
目标锚定（每段）场景生成 prompt 注入 objective + 最近 3 个 flag 的硬约束：「本段剧情必须推进或回扣当前目标，不可开无关新线」；生成完成后做一次轻量回扣检查（LLM 判断：本段是否推进目标？未推进则附带修正指令重写一次）主线漂移、剧情注水、flag 遗失
状态校验器（每 3 段）复用 consistency_validator 思路：LLM 对比「最近 3 段场景原文 vs state.json」，输出矛盾点列表（角色立场反转无铺垫/地点时间线冲突/关系值不匹配）→ 矛盾点作为修正指令注入下一段生成累积矛盾（第 10 段的设定忘了第 3 段）
偏离熔断（连续 2 次校验不过）触发「剧情回拉」：LLM 生成一段 自洽解释/回调段落（如"他忽然想起城隍庙的约定，调转马头"），并同步修正 state.json 中过期条目严重偏线——不让错误剧情继续滚雪球
存档快照（每段生成前）每段场景开始前自动备份 state.json 到 checkpoints/（保留最近 10 份），前端提供「↩ 回退到上一场景」兜底：即使校验没拦住，玩家可手动回退
节奏设计：目标锚定 = 每段都做（0.5 次 LLM 轻调用）；状态校验 = 每 3 段做一次（约 1 次调用）；熔断 = 罕见路径。平均每场景新增 ≈0.8 次轻量 LLM 调用，成本增加 15% 换主线不飘。

6. 核心机制：对话系统

对话引擎 = 本次新建的公共模块，同时服务「互动小说」和「角色扮演养成」两个功能。

6.1 对话上下文组装（成本控制）

角色卡（蒸馏）+ 声音卡+ 剧情状态摘要+ 最近 10 轮消息= ≈3-4k tokens/轮
  • 每 50 轮触发摘要压缩（复用 chapter_summarizer），旧对话归档到 chat_logs.jsonl（append-only，可回溯）
  • 对话采用 SSE 流式（复用 _sse_with_heartbeat），打字机效果 + 心跳保活
  • 角色扮演 System Prompt 约束：忠于人设卡、禁 OOC、按声音卡说话
  • 玩家输入自由文本（可含动作描写，如"（压低声音）…"）

6.2 对话中的多角色处理

关键节点可能有多位角色在场。方案：单轮对话锁定"当前交流对象"——玩家发消息时若 @角色名（如"@苏晚 你说呢"）或剧情指定，则切换交流对象；LLM 输出时若需第三方插话，允许一次回复中带多段 [角色名]: 台词（前端按角色分气泡 + 各自语音）。

6.3 角色人设不崩 — 四道防线

问题：对话多轮后角色容易 OOC（Out of Character）——说话变味、性格漂移、与设定矛盾。方案：四道防线逐层拦截。

① 人设卡三明治→ ② 动态行为档案→ ③ OOC 实时校验→ ④ 玩家标记纠正
防线实现兜住什么
① 人设卡三明治（每轮都注入）对话 prompt = 人设卡（心智模型/决策启发式/表达DNA/反模式/边界）+ 声音卡（口头禅/句式/情绪表现）+ 剧情状态，三层包裹。尤其利用女娲框架的「反模式」字段：显式列出"这个角色绝不会做的事/绝不会说的话"作为硬禁止基础 OOC——性格底色错位、说话不像本人
② 动态行为档案（每 20 轮）生成"角色行为档案"：从最近 20 轮对话提炼该角色表现出的具体行为倾向（"对玩家从戒备转为信任，开始主动分享秘密"）——替代原始聊天记录进入上下文，比静态人设卡更贴当前关系阶段长期对话的角色漂移（20 轮后行为惯性丢失）
③ OOC 实时校验（每 10 轮抽检）复用 humanize_pipeline 的检测器思路：一次轻量 LLM 调用检查最近 10 轮台词是否符合人设卡 + 行为档案，返回违规台词列表 + 原因 → 违规台词打回重写 1 次（带原因），仍不过则保留并标记给玩家漏网之鱼——单句台词明显出戏
④ 玩家标记纠正（人工闭环）对话气泡旁「⚠️ 人设崩了？」按钮 → 记录该台词 + 玩家理由 → 写入角色卡修正记录，后续对话注入「此角色曾被指出 X 问题，注意避免」AI 校验的盲区——玩家主观觉得不对劲的，AI 未必判得出
成本核算：人设三明治 ≈ 0 成本（复用已有卡）；行为档案 20 轮 1 次调用（约 1.5k tokens）；OOC 抽检 10 轮 1 次调用；玩家标记零成本。单轮对话平均成本增幅 <10%，换来的是角色从"不崩"到"越聊越像活人"。

8. 质量保障体系（五问五答）

本节回答五个"怎么保证"：① 暂停节点合适；② 剧情走向不偏移；③ 角色人设不崩；④ 内容不出 bug；⑤ 对话内容真实有效作用到剧情。前三个的机制分别在 §5.2 / §5.5 / §6.3 详述，第五问的 PACT 因果闭环在 §5.3 详述，本节汇总为一个端到端质量护栏总览 + 第④问的完整工程防御清单 + 第⑤问的因果一致性护栏。

8.1 端到端质量护栏总览

8.2 护栏 A：内容格式硬约束（防"生成垃圾")

  • 标记语言而非自由 JSON：场景/对话输出统一用轻量标记（【旁白】… / 【苏晚】… / 【动作】…），比 JSON 更抗 LLM 格式漂移，解析失败率低一个数量级
  • schema 校验：解析后校验必填字段（说话人/正文），缺字段用默认值兜底（缺说话人 → 归入旁白），解析失败自动重试 1 次（复用 ResilientLLMClient 重试）
  • 降级链：LLM 返回空/异常 → 重试 → 仍失败则生成固定兜底文本（"…远处传来更鼓声，故事还在继续"），绝不抛 500
  • 输入校验：玩家输入限长（500 字）、非法字符过滤、空输入拦截

8.3 护栏 B：状态机与超时（防卡死/防断线）

场景熔断策略
场景生成超时120s 超时 → 中止并返回已生成部分（半截场景也能渲染）+ 提示重试
节点判定失败规则兜底（连续 2 段必触发），绝不阻塞主流程
对话卡住单轮 60s 超时 → 流式结束并显示「角色还在思考…可再试一次」；「▶ 继续剧情」任何时候可用，可强制退出对话进入 PACT 提取
断线重连SSE 心跳（5s ping，沿用批量生成方案）+ 前端自动重连 2 次 → 重连后 GET /state 恢复渲染（状态在服务端，不丢进度）
并发限流互动模式限 2 并发/用户（LLM 调用排队），触发 429 时前端提示稍等而非报错

8.4 护栏 C：存档与回退（防数据损坏）

  • 原子写：state.json 写入用"临时文件 + rename"（复用记忆层乐观锁），崩溃不会写坏一半
  • 快照回退：每段场景生成前自动快照（保留 10 份），前端「↩ 回退一步」= 恢复上一快照
  • 日志重放修复：state.json 校验失败（schema 损坏）→ 从 scene_logs.jsonl（append-only 场景原文）重放重建状态，存档永不丢失
  • 语音缓存清理：tts_cache 7 天 TTL 自动过期（已有），超限（如 >500MB）按最旧清理

8.6 护栏 E：对话→剧情因果一致性（第五问专属）

针对"对话内容真实有效作用到剧情"，在 PACT 闭环（§5.3）之上再加三道运行时护栏：

护栏实现兜住什么
提取完整性PACT 提取 prompt 含反例约束：「玩家的明确承诺/行动/透露的信息必须逐条提取，一条都不能漏；宁可多提 low severity 项」；提取后做一次 round-trip 校验（轻量：把 facts 摘要给 LLM，问"对话中还有没有重要事实没被提取"，防漏网）提取遗漏——说了话但没进入剧情状态
注入可见性active facts 在生成 prompt 中置于「必回扣」专区（独立于普通上下文），LLM 输出后由回扣验证器确认"本段提到哪个 fact"；验证器结果回写 fact 的 evidence 字段注入被无视——状态里有但生成时当不存在
玩家可感知「你的影响」面板 + 台词高亮「🔗 呼应」标注 + 兑现/破裂推送（§5.3 ⑤）——生效与否玩家一眼可见，任何环节失效都会以"玩家发现"形式暴露黑盒失效——玩家以为系统没听到自己说话
质量保障成本汇总：内容格式 + 超时 + 存档 + 测试 ≈ 1.5-2 人日（Phase 1 内），运行时 LLM 成本增幅约 20-25%（目标锚定+回扣验证 0.8 次 + PACT 提取 1 次/对话 + OOC 抽检 0.1 次 + 校验 0.3 次/场景），换来的是五问全部有明确兜底——尤其是第五问：说了的话必被提取、必被注入、必被回扣、必被玩家看见。

角色 OOC / 台词同质中四道防线：人设卡三明治（含反模式禁止项）+ 动态行为档案 + OOC 抽检打回 + 玩家标记纠正（§6.3）
语音延迟破坏沉浸感中预合成流水线 + 磁盘缓存（实测 13ms 命中）+ 台词短（20-60 字 2s 合成）；极端情况降级静默重播
对话轮数失控（用户无限聊）低无上限但每轮成本仅 ~1.5k tokens；50 轮摘要压缩防膨胀；「继续剧情」随时可点
Android WebView 自动播放限制中首句由用户点击触发；后续播放延续同一手势上下文；失败显示 🔊 手动播放
对话内容没作用到剧情（提取遗漏/注入被无视）中PACT 因果闭环五环节：结构化提取（防漏）+ 事实生命周期（active→fulfilled/expired/broken）+ 双通道注入（硬挂钩必回扣）+ 回扣验证器（三方一致）+ 玩家可见（面板/高亮/推送），任何环节失效都会暴露给玩家（§5.3 / §8.6）
互动存档损坏低原子写（tmp+rename）+ 每段快照（保留 10 份）+ scene_logs 重放重建，存档永不丢失（§8.4）
质量保障增加 LLM 成本低全部用轻量调用（几百 token）+ 规则预筛减少 LLM 判定次数，总增幅 ~20-25%，每场景仍不到 ¥0.002

16. 结论与建议

结论：方案可行，且与现有系统契合度极高。互动小说模式本质上是把已有的三块资产（人设蒸馏、声音卡、免费 TTS）拼成一个新的交互范式——从"AI 帮你写小说"升级为"AI 陪你演小说"。

关于五个"怎么保证"的最终答案：

  • 暂停节点合适 → 规则预筛（保节奏下限）+ LLM 精判（防注水）+ 玩家主动介入（完全兜底），三层叠加，任何一层失误都不影响体验；
  • 剧情不偏移 → 目标锚定每段回扣 + 状态校验器扫矛盾 + 偏离熔断回调 + 快照回退，主线漂移有 4 道拦截；
  • 人设不崩 → 人设卡三明治（含反模式禁止项）+ 动态行为档案 + OOC 抽检打回 + 玩家标记纠正，OOC 有 4 道防线；
  • 内容不出 bug → 标记语言硬约束 + 超时熔断 + 原子写/快照/日志重放 + 6 组压力剧本测试，工程防御 4 类护栏全覆盖；
  • 对话真实作用到剧情 → PACT 因果闭环：结构化提取（承诺/行动/秘密逐条不遗漏）→ 事实生命周期（待兑现/已兑现/破裂）→ 双通道注入（硬挂钩必回扣 + 软影响角色态度）→ 回扣验证（三方一致才闭环）→ 玩家可见（面板/高亮/推送）——说了的话必被提取、必被注入、必被回扣、必被看见。

建议：

  • 先做 Phase 1 文本版验证手感——对话驱动分支的"剧情味"是否成立，一个周末即可验证，再投入语音打磨；
  • 质量保障机制必须进 Phase 1——五问的保障不是"上线后优化"，而是架构的一部分（目标锚定/节点三层保障/OOC 防线/PACT 因果闭环都在 Phase 1 内实现）；
  • 对话引擎独立成公共模块——一次开发，互动小说 + 角色扮演养成双功能受益，避免将来重复建设；
  • 语音按用户要求只对话题生效——旁白静默既符合需求又省一半 TTS 调用；
  • 音色映射先做规则版（性别/年龄 → 音色表），LLM 推荐版作为 Phase 2 增强——规则版 0 成本且已覆盖 90% 场景。

技术栈全部基于已验证组件（DeepSeek + edge-tts + SSE + Vue3），无新技术风险。预估总投入 7.5-9 人日（含质量保障），两周末可完成全功能。
