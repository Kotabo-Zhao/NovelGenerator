# 小说世界参与契约 4.3

## 开局与原著依据

玩家选择原著人物、进入章节、剧情规则和个人目标。AI 负责环境与 NPC；玩家的关键言行不由 AI 代写。

`entry-options` 枚举大纲和正文，按章节编号关联。缺失正文时明确降级到大纲，不用后续章节补空缺。进入章节之前的正文建立带来源的段落索引；当前章正文是事件参考，不能把其中玩家尚未执行的行为当成既成事实。未来章节正文不读取到本轮生成上下文。

当前章至多读取 200,000 字，过去章节每章最多索引 200 段、每段 1,000 字，保留最近 1,600 段。生成按查询与当前事件检索相关片段，并限制上下文长度。长篇复杂事实可能需要更多来源；这不是完整语义知识图谱。开局物品、位置及在场人物的模型建议需要逐字原文引用，玩家持有物品还需引用包含玩家名字；没有依据的字段不添加，并在界面说明依据不足。

## 行动与事件是不同层次

`意图 → 前置检查 → 执行裁定 → 状态提交 → 事件判定 → 后果叙述`。

- `success`：实际执行已提交；不代表必然完成当前事件。
- `failure`：缺少物品、目标离场、能力或世界限制等使行动未成功。
- `refused`：玩家未执行。明确选择拒绝当前事件时，允许分支模式记为 `declined`，不发完成奖励。
- `pending`：条件设想、信息不足或模型不可用；不默认为成功。

移动遵循现有地点图谱及未知地点确认流程。抵达只意味着到场，不自动算交付或履约。交付验证物品持有与接收者在场，成功后从玩家库存移入接收者库存。拾取只能取得场景中已确认的物品。消耗品在裁定成功后扣除。复杂交涉、救援、使用及战斗仍由模型在当前证据和属性约束下裁定，但不能借返回值任意增加物品、金钱或能力。普通救援不能使已死角色复活。

事件完成检查真实执行结果、事件条件、地点、物品和具名角色，不再按两个共同汉字、地点关键词或超时自动完成。同一行动结果只能结算一次。成功事件才应用节点产出；拒绝没有这些产出。保守参与模式限制关键救援 / 战斗改写；它是保守规则集，不是原著每句话的严格复刻。

每次执行保存有 ID 的行动记录，事件记录关联行动 ID。库存、伤亡、离场等权威字段不再从生成散文中反向提取。对话 PACT 中未经核实的信息标记为对话说法，不能取代实际行动结果。原著参考与本局冲突时，本局已提交结果优先。

## 存档与界面

同一本小说继续使用独立的 interactive 存档，不写回原著 chapters。旧存档可保留进度升级，升级前快照；旧完成记录不重演。回退恢复状态及日志，重开保留既有备份机制。

页面突出正文，将常驻人物栏和行动状态栏改为按需打开。可展开的身份 / 事件面板显示玩家是谁、当前事件、正文或大纲来源、执行原因、物品变化及本局分支。对话与动作模式明确传入 API；没有 NPC 时也能执行观察和移动。

## 验证范围

专项回归覆盖拒绝与条件语句、前置条件、库存转移、错误接收者、角色离场、失败移动、到场与履约区分、救援结果持久化、严格引用、正文缺章、未来内容隔离、事件超时、旧进度升级以及动作模式无 NPC 的情况。

浏览器完整流程使用隔离小说与模拟模型验证第二章开局、拒绝交信、实际交付和页面刷新。真实模型的判断质量、长时间叙事一致性及安卓真机键盘 / 后台行为仍需要真实使用验收。
