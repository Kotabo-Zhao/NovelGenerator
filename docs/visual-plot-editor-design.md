# 剧情画布 — 图形化剧情编辑器设计

> v1.0 | 2026-07-25 | 理念：像搭积木一样编剧情

---

## 一、设计理念

当前的编辑器本质是「JSON 表单」——填字段、点保存。对写作者不友好。

**目标**：做一个图形化的「剧情画布」，操作方式类似：
- **Unreal Blueprints**（节点连线）
- **Miro 白板**（自由排布）
- **Figma 画布**（缩放拖拽）

核心交互：**所见即所得，拖拽即编辑，连线即关联。**

## 三、交互模型

### 3.1 核心手势

| 手势 | 效果 |
|:-----|:-----|
| **单击节点** | 选中，底部显示详情+快捷操作 |
| **双击节点** | 打开详细编辑浮窗 |
| **拖拽节点** | 移动事件到新章节/新紧张度 |
| **Ctrl+拖拽** | 复制节点到新位置 |
| **Shift+点击** | 多选（批量操作） |
| **右键** | 上下文菜单（编辑/删除/关联/复制） |
| **滚轮** | 缩放画布 |
| **中键拖拽** | 平移画布 |
| **拖拽连线手柄** | 创建因果关联 |

### 3.2 节点类型

每种节点有独特的视觉形态：

```
┌─ 事件节点 ─────────────┐
│  ●  Ch5                │  ← 圆形，颜色=紧张度
│  发现真凶线索           │
│  ████████░░ 紧张度 8   │
└────────────────────────┘

┌─ 角色节点 ─────────────┐
│  👤 沈清许              │  ← 圆角矩形，头像占位
│  📍东宫  😢悲伤         │
│  🎯越狱                 │
└────────────────────────┘

┌─ 伏笔节点 ─────────────┐
│  📌 玉佩秘密            │  ← 菱形/书签形
│  Ch3 ──────────→ Ch12  │
└────────────────────────┘

┌─ 因果连线 ─────────────┐
│  Ch3·找到线索           │
│       ↓ (虚线箭头)       │  ← 跨泳道曲线
│  Ch8·揭穿真凶           │
└────────────────────────┘
```

### 3.3 操作流程示例

**场景：用户想把"找到线索"这个事件从 Ch3 挪到 Ch5**

```
当前：时间线上 Ch3 位置有一个事件节点
操作：拖拽事件节点 → 水平拖动到 Ch5 刻度线 → 松手
结果：节点吸附到 Ch5，自动保存，事件 chapter 字段更新
```

**场景：用户想创建一条因果链**

```
操作：点工具栏 [🔗连线模式]
     → 点击源节点（Ch3·门派被灭）出现连线手柄
     → 拖拽到目标节点（Ch8·揭穿真凶）
     → 弹出确认框 "门派被灭 → 揭穿真凶？" [确认]
结果：泳道间出现虚线箭头，因果链写入 storygraph
```

**场景：用户想新增一个事件**

```
操作：右键泳道空白处 → [➕ 在此处新增事件]
     → 浮窗输入事件描述 → [确认]
结果：新事件出现在点击位置对应章节，自动保存
```

## 四、三层视图切换

不是删掉现有面板，而是新增一个视图模式：

| 视图 | 用途 | 目标用户 |
|:-----|:-----|:--------|
| 📋 **列表视图**（现有） | 精确查看/搜索/批量管理 | 需要精确数据时 |
| 📊 **图表视图**（现有关系图+时间线） | 宏观俯瞰 | 快速了解结构 |
| 🎨 **画布视图**（新增） | 自由编辑/可视化操作 | **日常使用的主界面** |

切换方式：子标签栏增加 `🎨 画布` 按钮。

## 五、技术方案

### 5.1 技术选型

两种路线：

| 方案 | 技术 | 优势 | 劣势 |
|:-----|:-----|:-----|:-----|
| A: 纯 SVG | 现有 SVG + JS 事件 | 零依赖，与现有代码一致 | 复杂交互难实现（选中框、吸附、多选） |
| B: Canvas 2D | HTML5 Canvas + 自绘 | 性能好，完全控制渲染 | 需要重新实现所有渲染逻辑 |
| **C: 纯 DOM** | **绝对定位 div + CSS transform** | **最灵活，事件处理原生，可复用 Vue** | 大量节点时性能需优化 |

**推荐方案 C**：用绝对定位的 DOM 元素做节点，CSS transform 做缩放平移。每个节点是一个 Vue 组件（或 v-for div），事件处理直接用 DOM 事件。

### 5.2 核心数据结构

```javascript
// 画布状态
const canvasState = reactive({
  zoom: 1,
  panX: 0, panY: 0,
  selectedNodes: [],       // 多选
  connectMode: false,       // 连线模式
  connectSource: null,      // 连线起点
  dragging: null,           // 拖拽中的节点
});

// 节点布局（从 storygraph 数据计算）
const canvasNodes = computed(() => ({
  events: [],     // {id, ch, lane, label, tension, x, y}
  characters: [],  // {id, name, x, y, avatar, state}
  foreshadows: [], // {id, desc, from, to, x1, x2, y}
  links: [],       // {from, to, type, d(路径)}
}));
```

### 5.3 画布渲染

```html
<div class="sg-canvas" ref="canvasWrap"
     @wheel.prevent="zoomCanvas"
     @mousedown="startPan"
     @mousemove="doPan"
     @mouseup="endPan">
  
  <!-- 网格背景 -->
  <div class="sg-canvas-grid" :style="gridStyle"></div>
  
  <!-- 时间轴刻度 -->
  <div class="sg-canvas-axis">
    <div v-for="ch in chapters" class="axis-tick" :style="{left:chToX(ch)+'px'}">
      Ch{{ ch }}
    </div>
  </div>
  
  <!-- 事件节点 -->
  <div v-for="ev in canvasNodes.events" :key="ev.id"
       class="sg-canvas-node event-node"
       :class="{selected: isSelected(ev.id), dragging: canvasState.dragging===ev.id}"
       :style="{left:ev.x+'px', top:ev.y+'px', borderColor:ev.color}"
       @mousedown.stop="startDragNode(ev)"
       @dblclick="editEvent(ev)"
       @contextmenu.prevent="showContextMenu(ev, $event)">
    <div class="node-ch">{{ ev.ch }}</div>
    <div class="node-label">{{ ev.label?.substring(0,12) }}</div>
    <div class="node-tension" :style="{background:tensionColor(ev.tension)}"></div>
  </div>
  
  <!-- 连线层 (SVG overlay) -->
  <svg class="sg-canvas-svg" :viewBox="svgViewBox">
    <path v-for="link in canvasNodes.links" :d="link.d" .../>
  </svg>
  
  <!-- 选中框 -->
  <div v-if="canvasState.selectedNodes.length" class="sg-selection-box" .../>
</div>
```

### 5.4 连线模式

```
连线模式激活时：
1. 所有节点显示连线手柄（小圆点）
2. 点击手柄开始拖拽
3. 拖拽到另一个节点的手柄上 → 创建关联
4. 拖拽到空白处 → 新建节点
5. 按 Esc 或再次点击 [🔗] 退出连线模式
```

## 六、与现有系统的关系

```
storygraph.json ←── 读写 ──→ 画布编辑器
       ↓                           ↓
  写作管线                      实时预览
  (自动注入)                  (即时反馈)
```

**关键原则**：
- 画布编辑器和列表编辑器**共享同一份数据**（storygraph.json）
- 在一个视图的修改，切换到另一个视图**立即可见**
- 画布上的操作最终都转化为 API 调用（PUT/POST quick-action）

## 七、实施路线

### Phase 1: 画布基础（3h）
- 画布容器 + 缩放平移
- 时间轴刻度渲染
- 事件节点渲染（从 storygraph 数据映射）
- 拖拽移动节点 → 自动保存
- 右键菜单（编辑/删除）

### Phase 2: 连线系统（2h）
- 因果连线渲染（SVG overlay）
- 连线模式交互
- 视觉反馈（拖拽时预览线）
- 连线保存到 storygraph.causal_links

### Phase 3: 角色面板（1.5h）
- 左侧角色节点渲染
- 从画布拖拽角色到泳道 → 关联角色到线程
- 双击编辑角色状态

### Phase 4: 增强交互（2h）
- 多选 + 批量操作
- 吸附对齐（对齐章节刻度线）
- 动画过渡
- 撤销/重做
- 小地图

## 九、预期效果

操作一个剧情变更的典型流程：

```
现在（文字编辑器）:
  → 找剧情线 tab → 找到卡片 → 点编辑 → 改字段 → 点保存 → 回列表确认
  ≈ 6步，需要阅读文字定位

画布编辑器:
  → 在时间线上拖拽事件节点到新位置 → 自动保存
  ≈ 1步，纯视觉操作
```

这就是「图形化编程」的思路——**能拖的不用点，能点的不用敲，能看的不用读。**
